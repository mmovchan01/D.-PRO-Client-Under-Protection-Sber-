# D. PRO: Клиент под защитой (Сбер)

Воспроизводимое решение задачи регрессии для предсказания `protection_score`.

## Итоговая модель

Финальная модель — компактный сигмоидально-линейный индекс:

```text
protection_score = 100 * sigmoid(intercept + standardized_numeric_features @ coefficients)
```

Она использует 52 числовых признака, не использует `customer_id` и не кодирует категориальные поля. Пропуски в числовых данных заполняются медианами, признаки стандартизуются. Коэффициенты подбираются L-BFGS-B непосредственно по MSE на исходной шкале 0–100 с небольшой L2-регуляризацией; логит-линейная модель применяется только для начального приближения оптимизатора.

Проверялись линейные и сплайновые модели, MLP, SVR, ExtraTrees, LightGBM, XGBoost, Explainable Boosting Machine (EBM) и CatBoost, а также разные наборы признаков, взаимодействия и преобразования цели. На одном и том же случайном holdout-разбиении 80/20 с seed 42 результаты лучших вариантов составили:

| Модель | Holdout RMSE |
| --- | ---: |
| Сигмоидально-линейная, оптимизация на исходной шкале | **10.2178** |
| Сигмоидально-линейная со сплайнами | 10.2087 |
| CatBoost | 10.2723 |
| SVR (RBF) | 10.2758 |
| MLP | 10.2972 |
| XGBoost | 10.3591 |
| LightGBM | около 10.41 |
| EBM с взаимодействиями | 10.6341 |
| ExtraTrees | около 11.2 |

Хотя spline-вариант оказался немного лучше на одном holdout, его пятиблочный OOF RMSE составил 10.1836 против **10.1586** у выбранной более компактной модели с 52 коэффициентами признаков и свободным intercept. Поэтому финальной оставлена сигмоидально-линейная модель: она стабильнее по OOF и проще для воспроизведения и объяснения. Все оценки получены только на `hard_train.csv`; `hard_test.csv` использовался только для формирования submission. Порог RMSE 7 пока не достигнут — эту модель нельзя считать прошедшей критерий.

## Установка и запуск

Проверенная среда: Python 3.11.2. Установите зафиксированные зависимости:

```bash
python -m pip install -r requirements.txt
```

Обучение (читает только размеченный train, проверяет модель на holdout, затем переобучает на всём train и сохраняет веса):

```bash
python train.py --train-csv hard_train.csv --seed 42 --model-dir artifacts
```

Предсказание без обучения:

```bash
python predict.py --input-csv hard_test.csv --model-dir artifacts
```

Будет создан `submission_seed_42.csv` с колонками `customer_id,protection_score`. Для закрытого или другого тестового файла передайте путь в `--input-csv`; скрипт предсказания использует сохранённые веса и не обучает модель. Seed можно менять параметром `--seed` при обучении: он записывается в метаданные и в имя submission.

## Файлы решения

- `train.py` — holdout-проверка, обучение и сохранение весов.
- `predict.py` — загрузка готовых весов и создание CSV без обучения.
- `model_utils.py` — подготовка числовых признаков и параметры предобработки.
- `artifacts/protection_score_logistic.npz` — коэффициенты и параметры предобработки финальной модели.
- `artifacts/model_metadata.json` — seed, версии библиотек, признаки и метрика валидации.
- `artifacts/feature_coefficients.csv` — стандартизованные коэффициенты модели для интерпретации.
- `submission_seed_42.csv` — предсказания для доступного `hard_test.csv`.
- `requirements.txt` — фиксированные версии библиотек.
