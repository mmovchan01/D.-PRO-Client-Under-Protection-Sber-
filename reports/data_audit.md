# Аудит данных и устойчивость предсказания

Дата проверки: 2026-10-09. Данные: `hard_train.csv` (10 000 строк), `hard_test.csv` (2 000 строк, открытый тест).
Закрытый тестовый набор (`private_test`) на момент проверки недоступен, поэтому его свойства не проверялись.

## 1. Расхождения пропусков с описанием задачи

| Признак | В описании задачи | `hard_train.csv` | `hard_test.csv` |
| --- | --- | --- | --- |
| `house_value` | ~62% NaN | 4 671 (46.7%) | 922 (46.1%) |
| `car_value` | ~58% NaN | 4 103 (41.0%) | 831 (41.6%) |
| `average_claim_cost` | NaN при `number_of_claims = 0` | 3 959 (39.6%) | 803 (40.2%) |
| `credit_score` | NaN при малом сроке (thin file) | 0 | 0 |
| `customer_loyalty` | может отсутствовать | 0 | 0 |
| `marketing_response` | может отсутствовать | 0 | 0 |
| `health_index` | может отсутствовать | 0 | 0 |
| `days_since_last_login` | NaN без цифровой активности | 0 (есть 1 429 нулей) | 0 |
| `smartphone_age` | NaN, если смартфон не зарегистрирован | 0 | 0 |

Выводы:

- Доли пропусков `house_value` и `car_value` в данных ниже, чем в описании. Для `average_claim_cost` NaN совпадает с условием `number_of_claims = 0` (проверено на 100% строк).
- Признаки, которые по описанию бывают пустыми (`credit_score`, `customer_loyalty`, `marketing_response`, `health_index`, `days_since_last_login`, `smartphone_age`), в обоих файлах полностью заполнены. Либо описание не соответствует данным, либо пропуски были удалены при подготовке файлов.
- Наличие пропусков в закрытом наборе **неизвестно**. Это предположение, а не факт из данных. Поэтому пайплайн закрывает оба риска (см. раздел 3).

## 2. Поведение предыдущего `predict.py` при пропусках

Проверено на копии `hard_test.csv`:

- NaN в числовых колонках (`credit_score`, `customer_loyalty`, `region`): **не приводил к ошибке**. Числовые пропуски заполнялись медианами, а категориальные колонки в модели не используются.
- Отсутствующая колонка (например, полностью удалённый `credit_score`): **падал** с `ValueError: Input data is missing required feature columns`.

Значит, основной риск был не в NaN, а в отсутствии колонки. Это исправлено.

## 3. Что изменено в пайплайне

- `train.py`: обучение той же модели (MSE на шкале 0–100, L-BFGS-B, L2 = 1e4/n). Сохраняет веса, медианы и среднее/масштаб признаков, а также моды категориальных признаков (в `.npz` и в `model_metadata.json`). Seed задаётся `--seed`, без него выбирается случайный и записывается в метаданные.
- `predict.py`: без обучения. Добавляет отсутствующие колонки, заполняет NaN и нечисловые значения сохранёнными медианами, категориальные NaN — модами, печатает число заполненных значений по каждому признаку и пишет `submission_seed_{SEED}.csv`.
- Проверено:
  - чистый `hard_test.csv`: предсказания побитно совпадают с прежним `submission_seed_434089.csv`;
  - `hard_test.csv` с NaN в `credit_score` и `customer_loyalty` и с категориальными NaN: работает, NaN в выходе нет;
  - тест без колонки `credit_score`: работает с предупреждением;
  - тест, где `credit_score` и `customer_loyalty` полностью пусты, а `customer_loyalty` содержит текст `n/a`: работает, 2000 строк, NaN в выходе нет;
  - обучение с seed 434089 и seed 7 даёт одинаковые коэффициенты (разница 0.0).
- Категориальные признаки модель не использует. Их моды сохраняются, но на предсказание не влияют: в `reports/experiments.md` категориальные dummies не улучшили OOF RMSE.

## 4. Предел RMSE около 10.16

Метрики, полученные при аудите и повторной проверке:

| Модель | OOF RMSE (шкала 0–100) |
| --- | --- |
| Сигмоида от линейного индекса, MSE на шкале 0–100 (финальная модель) | 10.18 (5-fold, seed 434089) |
| Ridge на логит-шкале | 10.25 |
| Kernel ridge (RBF) на логит-шкале | 10.26 |
| LightGBM на логит-шкале | 10.39 |
| CatBoost, все признаки (ранняя остановка на фолдах, немного оптимистично) | 10.37 |
| LightGBM, все признаки, сырая цель | 10.52 |

Остатки на логит-шкале гауссовы (эксцесс около 0.07), однородны по децилям индекса и почти не зависят от признаков. Стандартное отклонение остатка около 0.60 у всех моделей. Нелинейные модели не снижают его.

Вывод: при доступных признаках RMSE около 10.2 — практический предел. Порог 7 требует остаточного шума около 0.4 на логит-шкале. Чтобы его получить, нужна скрытая структура, которую этот набор не содержит. Отдельно нужно проверить расхождения из раздела 1 у организаторов.
